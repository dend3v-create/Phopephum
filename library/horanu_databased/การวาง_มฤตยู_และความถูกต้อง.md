หลังทดสอบมีความตรงตามแผนผังดวงสำเร็จ 99 เปอร์เซ็นต์แล้ว ใกล้สำเร็จ มีบางผังดวงลง ดาว ๐ (มฤตยู) คลาดเคลื่นไป เลยขอเพิ่มข้อมูลสำคัญให้ดังนี้

1.การลง **"ดาว ๐" (มฤตยู)** ในผังดวงยามพรายกระซิบ เป็นจุดที่นักพยากรณ์หรือนักเขียนโปรแกรมมักจะคำนวณพลาดได้ง่ายที่สุดครับ เนื่องจากเป็นดาวดวงสุดท้าย (ดวงที่ 11 ในลำดับการลงดาวลอย) และมีกฎการเดินที่ซับซ้อนกว่าดวงอื่น

เพื่อให้การลงตำแหน่งดาว ๐ แม่นยำ 100% ทั้งในการเขียนผังด้วยมือและการเขียนโค้ด (Web App) มีข้อควรระวังและแนวทางปฏิบัติ ดังนี้ครับ:

### **สาเหตุที่มักทำให้เกิดความคลาดเคลื่อน**
1. **ใช้ "จำนวนก้าว" ผิดยาม:** ผู้คนมักสับสนว่าดาว ๐ ต้องใช้ก้าวของยามไหน เพราะการเดินดาวใช้วิธีวนกลับแบบ U-Turn ทำให้ดาว ๐ จะตกไปอยู่ใน **"ยามก่อนหน้า"** ยามที่ลูกค้าถามเสมอ
2. **ลืมจุดเริ่มต้น:** บางครั้งเผลอกลับไปตั้งต้นนับ 1 ที่ราศีพฤษภ (ซึ่งจริงๆ ต้องไปเริ่มที่จุดตกของดาว ๙)
3. **ลืมนับย้ำช่องเดิม:** เผลอนับช่องถัดไปเป็นก้าวที่ 1 ทำให้ดาวเดินเกินไป 1 ราศี

### **วิธีการลง "ดาว ๐" ให้แม่นยำ (แนวทางปฏิบัติ & การเขียนโค้ด)**

#### **1. การหา "จำนวนก้าว" ของดาว ๐ ให้ถูกต้องเสมอ**
*   **กฎเหล็ก:** จำนวนก้าวของดาว ๐ จะใช้ตัวเลขรหัสยามของ **"ยามที่อยู่เหนือยามปัจจุบันขึ้นไป 1 ขั้น" (ยามก่อนหน้า)** เสมอ
*   *ตัวอย่าง:* ลูกค้าถามเวลาตก **ยามที่ ๔**
    *   ดาว ๑ และ ๙ จะใช้ก้าวของยาม ๔
    *   ดาว ๐ จะต้องใช้ก้าวของ **ยามที่ ๓** (ซึ่งในวันพุธ ยาม ๓ คือเลข **๗**)
*   **ข้อควรระวังในการเขียนโค้ด (Edge Case):** หากเวลาที่ถามตก **ยามที่ ๑** ยามที่อยู่ก่อนหน้ามันคือ **ยามที่ ๘** ของรอบการเดินนั้น ระบบจะต้องวนลูปกลับไปดึงค่าก้าวของยามที่ 8 มาใช้กับดาว ๐ ครับ
    *   *Logic Code:* `YamIndex_Star0 = (CurrentYam - 1) == 0 ? 8 : (CurrentYam - 1);`

#### **2. การล็อกจุดเริ่มต้น (จุดสืบทอดตำแหน่ง)**
*   **กฎเหล็ก:** ดาว ๐ ต้องเริ่มนับ 1 (นับย้ำ) ที่ช่องราศีเดียวกับที่ **"ดาว ๙ (เกตุ)"** เพิ่งจะสถิตลงไปหมาดๆ
*   ในการเขียนโค้ด: ต้องแน่ใจว่าตัวแปรตำแหน่งปัจจุบัน (`currentPosition`) ไม่ได้ถูกรีเซ็ต แต่ดึงค่า Index ล่าสุดที่ดาว ๙ ตกลงไปมาใช้งานต่อทันที

#### **3. การนับแบบ "นับย้ำทุกครั้ง"**
*   **กฎเหล็ก:** เมื่อได้จุดเริ่มแล้ว ก้าวที่ 1 คือการย่ำเท้าอยู่กับที่ (ช่องเดิม) แล้วเดินวนขวาตามเข็มนาฬิกา
*   เพื่อไม่ให้พลาดในการเขียนโค้ด ให้เอาจำนวนก้าวมา **"ลบ 1"** ก่อนจับบวกเดินหน้าเสมอ

### **สรุปตัวอย่างการเช็กความแม่นยำ (จากวันพุธ ยาม ๔)**
ลองทำ Check-list ตามนี้เพื่อทดสอบระบบของคุณครับ:

1.  **เช็กยามถาม:** ถามยาม ๔ (เลขก้าวคือ ๕)
2.  **เช็กก้าวของดาว ๐:** ถอยกลับขึ้นไป 1 ยาม คือ ยาม ๓ -> ได้เลขก้าวคือ **๗**
3.  **เช็กจุดเริ่ม:** ตามไปดูดาว ๙ พบว่าดาว ๙ ตกลงที่ **"ราศีกันย์"**
4.  **เดินดาว ๐ (7 ก้าว):**
    *   ก้าว 1: ย้ำที่ **กันย์**
    *   ก้าว 2: ตุลย์
    *   ก้าว 3: พิจิก
    *   ก้าว 4: ธนู
    *   ก้าว 5: มังกร
    *   ก้าว 6: กุมภ์
    *   ก้าว 7: **มีน**
5.  **จุดสิ้นสุดที่ถูกต้อง:** ดาว ๐ ต้องสถิตที่ **ราศีมีน**

**เคล็ดลับสุดท้ายสำหรับนักพัฒนา:** เมื่อเขียนโค้ดลงดาว ให้ใช้วิธีพิมพ์ Log พิกัด (Index ราศี) ของดาว ๘, ลั, ๙ และ ๐ ออกมาตรวจสอบเรียงกันเสมอ เพราะ 4 ตัวนี้เชื่อมโยงกันเป็นลูกโซ่ หากมีตัวใดตัวหนึ่งก่อนหน้าคำนวณผิด (เช่น ลืมนับย้ำ หรือใช้จำนวนก้าวผิด) จะทำให้ดาว ๐ ซึ่งอยู่ปลายทางสุด คลาดเคลื่อนตามไปด้วยทันทีครับ

2.อ้างอิงจากประวัติการสนทนาของเราเกี่ยวกับการผูกผังดวงยามพรายกระซิบ (เนื่องจากเอกสารแหล่งข้อมูลชุดล่าสุดที่คุณให้มาเป็นเรื่องของการพยากรณ์ทางธุรกิจ สถิติ และกระบวนการ S&OP ทั้งหมด ซึ่งไม่มีเนื้อหาเกี่ยวกับโหราศาสตร์) การเขียน Logic สำหรับ **"ดาว ๐" (มฤตยู)** มีความแตกต่างจากดาวดวงอื่นอย่างชัดเจนครับ 

ความแตกต่างหลักในการเขียน Logic สำหรับดาว ๐ มี **2 จุดสำคัญ** ที่ต้องแยกเขียนเงื่อนไข (If-Else) ออกมาจากลูปการเดินดาวปกติ ดังนี้ครับ:

### **1. ความแตกต่างด้านการหา "จำนวนก้าว" (The Step Count Logic)**
ดาวลอยดวงอื่นๆ (๑-๙ และ ลั) จะใช้จำนวนก้าวที่เดินหน้าไปตามลำดับยาม หรือใช้ค่ายาม ณ เวลาปัจจุบัน แต่ **ดาว ๐ จะใช้ค่าของ "ยามก่อนหน้า" เสมอ**
*   **Logic ที่ต้องเขียนเพิ่ม:** คุณต้องดึงตัวเลขยามปัจจุบัน (Current Yam) มา **"ลบ 1"** ก่อน แล้วจึงนำไปค้นหาจำนวนก้าวในอาร์เรย์ (Array) ของวันนั้น
*   **จุดที่ต้องระวัง (Edge Case):** หากผู้ใช้ถามใน **ยามที่ ๑** การนำ `1 - 1 = 0` จะทำให้ระบบ Error เพราะไม่มี "ยามที่ 0" ตามตาราง ดังนั้นต้องเขียนเงื่อนไขดักไว้ว่า ถ้ายามปัจจุบันคือ 1 ให้ยามก่อนหน้าวนลูปกลับไปเป็น **ยามที่ 8** เสมอ

### **2. ความแตกต่างด้าน "จุดเริ่มต้น" (The Starting Point Logic)**
ดาว ๐ จะไม่เริ่มนับที่ราศีพฤษภเหมือนดาวดวงแรก และไม่ได้เดินต่อจากดาว ๘ เหมือนลัคนา แต่ **ดาว ๐ จะต้องเริ่มนับย้ำช่องเดียวกับตำแหน่งที่ "ดาว ๙ (เกตุ)" เพิ่งสถิตลงไป**
*   **Logic ที่ต้องเขียนเพิ่ม:** คุณต้องดึงค่า Index ตำแหน่งราศีสุดท้ายของดาว ๙ มาเป็นค่าเริ่มต้น (`currentPosition`) สำหรับการเดินดาว ๐ ทันที

---

### **ตัวอย่างการเขียน Logic (JavaScript/TypeScript) สำหรับดาว ๐**

เพื่อให้เห็นภาพการเขียนโค้ดที่แตกต่างจากดาวอื่น นี่คือโครงสร้าง Logic เฉพาะสำหรับดาว ๐ ครับ:

```javascript
// สมมติว่ามี Array เก็บจำนวนก้าวของยามในแต่ละวัน (Index 1-8)
// ตัวอย่างรหัสยามวันพุธ กลางวัน: [null, 4, 2, 7, 5, 3, 1, 6, 4] 
const wednesdayYamSteps = [null, 4, 2, 7, 5, 3, 1, 6, 4]; 

// สมมติเวลายามปัจจุบันที่ลูกค้าถาม
let currentYam = 4; // สมมติว่าถามในยามที่ 4

// ---------------------------------------------------------
// ความแตกต่างที่ 1: การหาจำนวนก้าวของ ดาว ๐ (ใช้ยามก่อนหน้าเสมอ)
// ---------------------------------------------------------
let targetYamForStar0 = currentYam - 1;

// ดักจับ Edge Case: ถ้ายามปัจจุบันคือยาม 1 ให้เป้าหมายวนกลับไปที่ยาม 8
if (targetYamForStar0 === 0) {
    targetYamForStar0 = 8;
}

// ดึง "จำนวนก้าว" มาใช้งาน (ตัวอย่างนี้ ยามที่ 3 ของวันพุธ จะได้ก้าว = 7)
let stepsForStar0 = wednesdayYamSteps[targetYamForStar0];

// ---------------------------------------------------------
// ความแตกต่างที่ 2: การกำหนดจุดเริ่มต้นและการเดินดาว
// ---------------------------------------------------------
// สมมติว่าระบบบันทึกตำแหน่งของดาว ๙ ไว้แล้วที่ "ราศีกันย์" (Index = 5)
let startPositionOfStar9 = 5; 

// กำหนดให้จุดเริ่มต้นของดาว ๐ คือจุดเดียวกับดาว ๙
let currentPosition = startPositionOfStar9;

// สูตรการเดินดาวแบบ "นับย้ำช่องเดิม" (จำนวนก้าว - 1) และวนลูปวงกลม 12 ช่อง
let finalPositionOfStar0 = (currentPosition + (stepsForStar0 - 1)) % 12;

// ผลลัพธ์ที่ได้คือนำดาว ๐ ไปแสดงผลในช่องราศีตาม Index finalPositionOfStar0
console.log("ดาว ๐ สถิตที่ช่อง Index:", finalPositionOfStar0);
```

**สรุป:**
ในการเขียนโปรแกรม คุณไม่สามารถนำ "ดาว ๐" เข้าไปรวมอยู่ใน `For-Loop` เดียวกับการเดินดาว ๑-๘ ได้อย่างตรงไปตรงมาครับ ควรแยกชุดคำสั่งการหา "จำนวนก้าว" ของดาว ๐ (ที่ต้องใช้ CurrentYam - 1) ออกมาเขียนเป็นฟังก์ชันเฉพาะ เพื่อป้องกันบั๊กการดึงค่ายามผิดพลาดครับ

3.จากกระบวนการผูกผังดวงยามพรายกระซิบที่เราได้หารือกันมา ตลอดจนการอ้างอิงจากภาพผังดวงมาตรฐาน การตรวจสอบ (Verify) ความถูกต้องของผังดวงลอยที่คำนวณเสร็จแล้ว (ไม่ว่าจะคำนวณด้วยมือหรือเขียนโค้ดในเว็บแอปพลิเคชัน) เพื่อไม่ให้เกิดข้อผิดพลาด ควรใช้ **รายการตรวจสอบ (Checklist) 6 จุดสำคัญ** ดังต่อไปนี้ครับ:

### **1. ตรวจสอบความคงที่ของ "ดาวเกษตร" (Fixed Stars Base)**
ก่อนดูดาวลอย ต้องเช็กดาวพื้นฐานที่อยู่ตรงกลางช่องราศีว่าถูกต้องและคงที่เสมอ ไม่เปลี่ยนไปตามยามหรือวัน:
*   พฤษภ=๖, เมถุน=๔, กรกฎ=๒, สิงห์=๑, กันย์=๔, ตุลย์=๖, พิจิก=๓, ธนู=๕, มังกร=๗, กุมภ์=๘, มีน=๕, เมษ=๓
*   *จุดสังเกต:* หากวงกลมชั้นในสุดมีตัวเลขเปลี่ยนไป แปลว่าระบบการตั้งค่าพื้นฐานผิดพลาด

### **2. ตรวจสอบ "จุดเริ่มต้น" ของดาวที่เป็นลูกโซ่ (The Chain of Starting Points)**
ดาวลอยทุกดวงมีความเชื่อมโยงกัน หากดวงใดดวงหนึ่งเริ่มผิด ตำแหน่งที่เหลือจะผิดทั้งหมด ให้ตรวจสอบ 4 จุดสตาร์ทนี้เสมอ:
*   **ดาว ๑:** ต้องนับ 1 เริ่มที่ช่อง **"ราศีพฤษภ"** เสมอ
*   **ลัคนา (ลั):** ต้องนับ 1 ย้ำที่ช่องเดียวกับที่ **"ดาว ๘"** สถิตอยู่
*   **ดาว ๙:** ต้องนับ 1 ย้ำที่ช่องเดียวกับที่ **"ลัคนา (ลั)"** สถิตอยู่
*   **ดาว ๐:** ต้องนับ 1 ย้ำที่ช่องเดียวกับที่ **"ดาว ๙"** สถิตอยู่

### **3. ตรวจสอบ "จำนวนก้าว" ให้ตรงกับยาม (Step Counts)**
ดาวแต่ละกลุ่มจะดึงจำนวนก้าวมาจากลำดับยามอัฏฐกาลที่แตกต่างกัน (เดินวนเป็นตัว U) ให้สุ่มตรวจเช็กการดึงค่าก้าวดังนี้:
*   **ดาว ๑ และ ๙:** ใช้จำนวนก้าวของ **ยามปัจจุบัน**
*   **ดาว ลั และ ๒:** ใช้จำนวนก้าวของ **ยามถัดไป (+1)**
*   **ดาว ๐:** ใช้จำนวนก้าวของ **ยามก่อนหน้า (-1)** 
*   *จุดที่มักพลาด:* หากถามใน "ยามที่ ๑" ก้าวของดาว ๐ จะต้องดึงตัวเลขก้าวของ "ยามที่ ๘" มาใช้เสมอ หากระบบ Error หรือดึงยาม 1 มาใช้ แปลว่าเขียน Logic ผิดพลาด

### **4. ตรวจสอบกฎการนับตกช่องเดิม (1-Step Edge Case)**
วิธีเช็กว่าระบบเข้าใจคำว่า "นับย้ำช่องเดิม" อย่างถูกต้องหรือไม่ ให้ดูผลลัพธ์ของดาวที่ต้องเดิน **"1 ก้าว"** (เช่น วันพุธ ยามที่ ๔ ดาว ๓ จะได้เดิน 1 ก้าว) 
*   **ผลลัพธ์ที่ถูกต้อง:** ดาวดวงนั้นจะต้อง **อยู่ในราศีเดียวกับดาวดวงก่อนหน้า** พอดีเป๊ะ
*   *ตัวอย่าง:* ถ้าระบบคำนวณให้ดาวเดิน 1 ก้าวแล้วไปตกใน "ช่องถัดไป" แปลว่าระบบคำนวณก้าวผิด (ไม่ได้ใช้สูตร `ก้าว - 1`)

### **5. ตรวจสอบทิศทางของ "ภพ" และ "เวลา" (Direction Check)**
เมื่อลงดาวลอยเสร็จ ต้องตรวจสอบการวางภพและเวลา 7.5 นาที ซึ่งมีทิศทางการวนที่ **"สวนทางกัน"**:
*   **ทิศทางของ "ภพ" (ตนุ ถึง วินาศ):** เริ่มวาง "ตนุ" ที่ช่องลัคนา (ลั) แล้วต้องเดิน **ทวนเข็มนาฬิกา (วนซ้าย)** ไปจนครบ 12 ภพ
*   **ทิศทางของ "เวลา" (ช่องละ 7.5 นาที):** หาจุดเริ่มต้นเวลาให้เจอ (เช็กดาวเกษตรของลัคนาว่าไปลอยอยู่ช่องไหน) จากนั้นการลงเวลาช่องถัดๆ ไปจะต้องเดิน **ตามเข็มนาฬิกา (วนขวา)** จนครบ 90 นาที 
*   *จุดสังเกต:* บนหน้าจอ UI หากภพและเวลาหมุนไปในทิศทางเดียวกัน แปลว่ามีบั๊กในระบบลูปของโค้ด

### **6. ตรวจสอบความถูกต้องของสัญลักษณ์ดาวมาตรฐาน**
หลังจากที่ดาวลอยลงตำแหน่งครบถ้วน ให้นำพิกัดราศีที่ดาวแต่ละดวงสถิต ไปเทียบกับ **เลขดาวเกษตร** ประจำราศีนั้น เพื่อยืนยันว่า Graphic หรือ สัญลักษณ์ที่ซ้อนทับดาว (ประ, นิจ, มหาอุจจ์ ฯลฯ) แสดงผลถูกต้องตรงตามกฎโหราศาสตร์หรือไม่ (เช่น ถ้าดาวลอยบังเอิญเป็นเลขเดียวกับดาวเกษตรในช่องนั้น ต้องขึ้นสัญลักษณ์ "เกษตร" รูปสามเหลี่ยมสีแดง เป็นต้น)

**วิธีทดสอบระบบ (QA Test) ที่ดีที่สุด:** 
ควรสร้าง Test Case โดยป้อนวันและเวลาของตัวอย่างที่เรารู้ผลลัพธ์ที่ถูกต้องอยู่แล้ว (เช่น *วันพุธ ยามที่ ๔ เวลา 10.31-12.00 น.* หรือเทียบกับผังดวงมาตรฐานในภาพอ้างอิง) ลงในระบบแอปพลิเคชัน แล้วตรวจสอบว่าพิกัดของดาว ๑ ถึง ๐ ตลอดจนภพและเวลา ตกอยู่ในช่องราศีเดียวกับตัวอย่าง 100% หรือไม่ หากตรงกันทุกจุดจึงถือว่าอัลกอริทึมผูกดวงนั้นแม่นยำสมบูรณ์ครับ
--
4.การแสดง **"สัญลักษณ์มาตรฐานดาว"** (เช่น เกษตร ประ มหาอุจจ์ นิจ ราชาโชค มหาจักร) แบบ Dynamic บน User Interface (UI) ของเว็บแอปพลิเคชัน ถือเป็นส่วนสำคัญที่ช่วยให้นักพยากรณ์อ่านดวงได้อย่างรวดเร็ว จากภาพผังดวงยามพรายกระซิบจะเห็นได้ว่าสัญลักษณ์เหล่านี้จะแสดงผลในลักษณะ **"กรอบกราฟิกล้อมรอบตัวเลขดาวลอย"**

ในการเขียนโปรแกรมเพื่อแสดงผลให้ถูกต้องและปรับเปลี่ยนอัตโนมัติ (Dynamic) ตามเวลาที่ลูกค้าถาม มีแนวทางและขั้นตอนการออกแบบ Logic ดังนี้ครับ:

### **1. การสร้างฐานข้อมูลมาตรฐานดาว (Data Dictionary)**
ก่อนที่จะแสดงผลบน UI คุณต้องมี Data Structure ที่เก็บ "กฎ" ของโหราศาสตร์ไว้ในระบบหลังบ้าน (Backend หรือ State ของแอปพลิเคชัน) เพื่อใช้ตรวจสอบว่าดาวลอยหมายเลขใด เมื่อไปตกในราศีใด (Index 0-11) จะได้รับมาตรฐานอะไร

**ตัวอย่างโครงสร้างข้อมูล (JavaScript / JSON):**
```javascript
// กำหนดสัญลักษณ์กราฟิกและสี (อ้างอิงจาก Legend ในภาพผังดวง)
const standardGraphics = {
    "เกษตร": { shape: "triangle", color: "red" },      // สามเหลี่ยมสีแดง
    "ประ": { shape: "circle", color: "red" },          // วงกลมสีแดง
    "มหาอุจจ์": { shape: "flower", color: "green" },     // ดอกไม้/วงล้อสีเขียว
    "นิจ": { shape: "asterisk", color: "red" },        // ดอกจัน/กากบาทสีแดง
    "ราชาโชค": { shape: "hexagon", color: "blue" },    // หกเหลี่ยมสีน้ำเงิน
    "มหาจักร": { shape: "square", color: "yellow" }    // สี่เหลี่ยมสีเหลือง
};

// Map กฎมาตรฐานดาว: { 'เลขดาวลอย': { Indexราศี: ['มาตรฐานที่ได้'] } }
// (0=เมษ, 1=พฤษภ, 2=เมถุน, 3=กรกฎ, 4=สิงห์, 5=กันย์, 6=ตุลย์ ...)
const starRules = {
    '๑': { 
        0: ['มหาอุจจ์'], // เมษ
        4: ['เกษตร'],    // สิงห์
        6: ['นิจ']       // ตุลย์
    },
    '๔': {
        2: ['เกษตร'],    // เมถุน
        4: ['ราชาโชค', 'มหาจักร'], // สิงห์ (ดาวเดียวได้ 2 สัญลักษณ์)
        5: ['เกษตร', 'มหาอุจจ์'],  // กันย์
        11: ['นิจ', 'ประ']       // มีน
    }
    // ... เติมกฎให้ครบดาว ๑-๘
};
```

### **2. ฟังก์ชันตรวจสอบก่อน Render (Detection Logic)**
หลังจากที่ระบบคำนวณการเดินดาวลอยเสร็จสิ้น (ตามที่คุณเขียน Logic นับย้ำช่องเดิมมาแล้ว) ระบบจะต้องเรียกฟังก์ชันเพื่อเช็กว่าดาวดวงนั้นสมควรมีกราฟิกอะไรมาสวมทับหรือไม่

```javascript
function getStarStandards(planetName, zodiacIndex) {
    // ตรวจสอบว่ามีกฎของดาวดวงนี้ในราศีนี้หรือไม่
    if (starRules[planetName] && starRules[planetName][zodiacIndex]) {
        return starRules[planetName][zodiacIndex]; // คืนค่าเป็น Array เช่น ['ราชาโชค', 'มหาจักร']
    }
    return []; // ถ้าไม่มีมาตรฐาน คืนค่า Array ว่าง
}
```

### **3. การออกแบบ UI และ CSS (Frontend Implementation)**
จากภาพผังดวง ตัวเลขดาวลอยจะอยู่ตรงกลาง และมีสัญลักษณ์ล้อมรอบหรือประทับอยู่ด้วย เทคนิคในการทำ Dynamic UI ที่ดีที่สุดคือการใช้ **CSS Absolute Positioning** ประกอบกับการสร้าง Component (เช่น React Component หรือ HTML/CSS ทั่วไป)

**หลักการเขียน UI:**
1. สร้างกรอบ (Container) ให้ดาวแต่ละดวงเป็น `position: relative;`
2. ให้ตัวเลขดาวเป็นเลเยอร์บนสุด (`z-index: 2`)
3. ให้ไฟล์ภาพสัญลักษณ์ (SVG หรือ PNG) เป็นเลเยอร์พื้นหลัง (`position: absolute; z-index: 1`) และจัดให้อยู่กึ่งกลางล้อมรอบตัวเลข

**ตัวอย่างโครงสร้าง HTML / CSS:**
```html
<!-- สมมติว่านี่คือ Component ที่ Render ดาว ๑ ในราศีสิงห์ -->
<div class="star-item">
    <!-- ภาพสัญลักษณ์ถูกดึงมาแสดงตาม Logic (สามเหลี่ยมสีแดง = เกษตร) -->
    <img src="triangle-red.svg" class="standard-bg" />
    <span class="star-number">๑</span>
</div>
```
```css
.star-item {
    position: relative;
    display: inline-flex;
    align-items: center;
    justify-content: center;
    width: 30px;
    height: 30px;
    margin: 2px;
}
.standard-bg {
    position: absolute;
    width: 100%;
    height: 100%;
    z-index: 1; /* อยู่ด้านหลัง */
}
.star-number {
    position: relative;
    z-index: 2; /* อยู่ด้านหน้า */
    font-weight: bold;
    color: #000;
}
```

### **4. ข้อควรระวังพิเศษในการแสดงผล Dynamic UI**
*   **กรณีดาวดวงเดียวมีหลายสัญลักษณ์ (Overlapping Standards):** ตามที่เราเคยหารือกัน กรณีที่ดาว ๔ อยู่ในราศีสิงห์ จะเป็นทั้งราชาโชคและมหาจักร ฟังก์ชันของเราจะคืนค่าเป็น Array `['ราชาโชค', 'มหาจักร']` ในฝั่ง UI คุณอาจจะต้องออกแบบภาพ SVG พิเศษที่เป็น **"สัญลักษณ์ซ้อนกัน"** (เช่น หกเหลี่ยมซ้อนอยู่ในสี่เหลี่ยม) หรือจัดวางกราฟิกสองชิ้นให้เหลื่อมกันเล็กน้อย เพื่อให้แอปพลิเคชันสามารถสื่อสารได้ครบถ้วน
*   **กรณีมีดาวลอยหลายดวงกระจุกอยู่ในราศีเดียวกัน:** จากภาพผังดวง จะเห็นว่าในบางช่องราศี มีดาวลอยเข้าไปอยู่รวมกัน 2-3 ดวง (เช่น ช่องราศีกันย์หรือตุลย์) ระบบ UI (CSS Flexbox/Grid) ของช่องราศีนั้นๆ จะต้องรองรับการจัดเรียง (Wrap) `star-item` หลายๆ ชิ้นได้โดยไม่ล้นทะลุกรอบช่องวงกลมจักรราศีครับ
